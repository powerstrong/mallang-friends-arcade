## 0. 한 줄 결론

**2인 결정론 SRPG로서 재미 천장은 낮다. 같은 엔진·자산·톤을 유지한 채 「결정론 전술 퍼즐」로 장르를 바꾸면 천장이 크게 올라간다.** 쫌쫌따리 밸런싱이 아니라 전투 코어를 교체한다.

---

## 1. 진단 — 무엇이 재미를 죽이는가 (두 리뷰 공통)

- **핵심 병목: "확실성은 있는데 개입력이 없다."** 적 미리보기는 미래를 100% 보여주지만, 플레이어가 그 미래에 할 수 있는 일은 피해를 ±1~2 조정하는 것뿐이다. 예측이 **장난감(toy)이 아니라 계산서(bill)**가 된다.
- **거짓 깊이(false depth):** 친구당 초기 합법수 18~31개지만 대부분 "같은 공격/막기/대기를 다른 칸에서" 하는 중복이다. 선택지는 많고 결과의 종류는 적다.
- **아키타입이 장식:** `chooseAiAction`이 `ai`/`role`을 안 읽어 삐걱봇·콩콩봇·포탑·곰이 포탑 이동력 0을 빼면 동일한 추적·공격 AI다. 외형 넷, 전술 질문 하나.
- **입력 비용 과다:** 일반 이동+공격이 `친구→이동칸→이동확정→적→공격확정` ≈ 5탭, 두 명이면 턴당 10탭. 결정의 얕음 대비 조작이 비싸다.
- **고정 피해는 문제가 아니다.** 고정 피해를 대신할 **위치 변화·밀기·유도·연쇄작용**이 없는 것이 문제다.
- 콘텐츠 3판이면 소진. 웹의 강점(데일리 시드·공유·즉시 재시작·언두)을 전혀 안 쓴다.

## 2. 새 코어 — "때리는 게임"에서 "예고된 적 행동을 재배선하는 게임"으로

한 판 = **60~120초, 3~5비트, 장난감 3~5대, 총 6~10개 명령.**

매 비트 시작에 **모든 장난감의 다음 행동이 보드에 고정 표시**된다(예고 = 보조가 아니라 게임 그 자체).

| 장난감 | 예고 | 재배선 포인트 |
|---|---|---|
| 삐걱봇 | 화살표 방향 3칸 돌진 | 방향을 틀거나 벽/다른 봇에 박게 |
| 콩콩봇 | 표시 칸으로 점프 후 상하좌우 1칸 진동 | 착지점을 바꿔 진동이 헛치게 |
| 반짝포탑 | 직선 4칸 재부팅 광선 | 광선 위에 다른 봇을 세워 대신 맞게 |
| 덩치곰(보스) | 1비트 준비 후 표시된 3×3 쿵 | 준비 중 제어별로 예고를 무력화 |

**플레이어가 10초마다 하는 결정:**
> "두 번의 명령으로 어느 위협을 없애고, 어느 위협을 장난감 수리 연쇄로 바꿀 것인가?"

친구 능력은 **숫자가 아니라 보드를 바꾼다.**
- **라떼(밀기):** 3칸 이내 이동 후 인접 장난감을 1칸 민다. 또는 광선/돌진 앞에 서서 1회 몸으로 막는다.
- **민트(당기기·조준):** 2칸 이내 이동 후 직선 사거리 3의 장난감을 1칸 당긴다. 또는 포탑 광선을 1칸 굴절시킨다.
- *(후속) 햄스터(쪼르르 밀기):* 직선으로 장난감 1대를 최대 2칸 밀어낸다. 3번째 동사 → 조합 깊이 확보.

**해결 = 동시 처리.** 두 친구 명령을 예약 → 비트 전체 결과가 즉시 미리 보임 → 큰 `출동!` 한 번으로 (친구 이동 → 장난감 예고 실행 → 충돌·수리 판정)을 1~2초에 해결. 숨은 순서 대신 동시 해결이 기본.

**장난감은 체력으로 멈추지 않는다(비폭력 톤 유지 = "수리").**
- 벽/다른 장난감과 충돌: 수리 게이지 −1
- 다른 장난감의 광선·돌진에 맞음: −2
- 빛나는 수리별 위 도착: 즉시 수리
- 한 행동으로 2대 이상 수리: **연쇄 보너스 + 강한 시청각 보상**

친구는 **2하트**만. 맞을 수 있으나 HP 교환이 목표가 아니다. 항상 **위협 수 > 명령 두 개**라, 좋은 해법은 **한 조작으로 두 문제를 푼다.**

**깊이는 스탯이 아니라 조합으로 확장:** ①빈 곳으로 밀어 회피 → ②수리별로 밀어넣기 → ③포탑 선상에 다른 봇 배치 → ④운반 경로와 연쇄 수리 동시 해결 → ⑤제어별로 곰 예고를 바꿔 자가수리.

**별 조건:** 1별 클리어 / 2별 친구·시설 피해 0 / 3별 목표 비트 이내 또는 2대 연쇄 수리.

## 3. 유지 · 재사용 (순수 엔진 그대로)

- 8×8(퍼즐은 5×5~6×6부터), 두 친구, 페이즈 구조, **결정론**
- 세 목표 계열: 길 확보 / 운반·탈출 / 제어별 활성화 → `evaluateObjective` 그대로
- 순수 상태/행동/예측/목표 엔진, 직렬화 상태, `data/*` 콘텐츠 분리
- 캐릭터·장난감 자산, Korean UI, localStorage, PWA, 무빌드 바닐라 JS, `file://`

### 엔진 매핑
- `listLegalActions`: 이동 목적지 + 밀기/당기기/막기를 합친 명령 생성, 결과 동일 경로 제거(중복 붕괴 해소)
- 장난감 `intent`: 비트 시작마다 `role`/`ai`로 결정론 계산(마침내 아키타입을 실제로 사용) — dash 방향, jump 착지, beam 직선, slam 구역
- `applyBeat(state, [cmdA, cmdB])`: 친구 이동 → 각 장난감 예고 실행 → 충돌·수리·목표 변화 순차 적용 → 이벤트 → 다음 예고 재계산
- `forecast`: 예약된 두 명령 이후 **비트 전체 결과**를 항상 보드에 표시(현재 `forecastEnemyPhase` 발전형)
- 직렬화 상태 + 행동 기록: **언두·리플레이·공유**에 재사용

## 4. 과감히 자를 것 (aggressive cut)

ATK/DEF/RNG 스탯·고정 피해 누적 · 기본 공격/반격/보스 HP 깎기 · 역할만 다른 추적 AI · 전멸 튜토리얼 · 이동확정+행동확정 이중 절차 · `대기`/수동 턴 종료/선택형 미리보기 · 목표칸 재확인 절차 · 전원 생존 별 · 가로 스크롤 보드 · 장비/성장/추가 캐릭터/긴 캠페인 · 긴 브리핑.

> **20개 짧은 수제 퍼즐 + Daily가 재플레이를 증명하기 전에는 로스터·캠페인을 늘리지 않는다.**

## 5. 웹·모바일을 게임성으로 (플랫폼 극대화)

- 항상 전체 보드가 한눈에, 주요 조작은 하단 엄지 영역
- 이동+능력 한 번에 예약, 비트당 확인은 `출동!` 하나
- **무제한 언두 + 한 비트 되돌리기**, 300ms 이하 즉시 재시작
- **오늘의 퍼즐(날짜 시드 + 검증 템플릿 조합)** — 모두 같은 판
- **공유:** URL 해시에 시드+행동 기록 → 같은 판·리플레이 공유. `file://`은 짧은 도전 코드 복사
- 스포일러 없는 결과 공유: `오늘 별빛작전 4비트 / 피해 0 / 2연쇄 ⭐⭐⭐`
- tiny download, 오프라인, localStorage 연속 기록·스트릭

## 6. 실행 로드맵 (검증 게이트)

1. **버티컬 슬라이스(프로토타입):** 5×5 한 판, 라떼(밀기)+민트(당기기), 삐걱봇 돌진 + 포탑 광선 + 수리별, 예약→출동→동시해결→언두. **"한 조작으로 두 위협 해결"의 손맛**을 실제로 검증.
2. 손맛 통과 시: 수제 퍼즐 12~20개 + 데일리 시드 + 공유.
3. 그 다음에야 햄스터(3번째 동사)·추가 예고·보스 슬램.

각 게이트 통과 전에는 다음 단계로 가지 않는다.

## 7. 핵심 문장

> **두 유닛이 문제가 아니라, 두 유닛의 행동이 미래를 거의 바꾸지 못하는 것이 문제다.** 플레이어가 적 페이즈를 *견디는* 대신 직접 *연출*하게 만들면, 현재의 결정론과 작은 규모는 약점이 아니라 정체성이 된다.
