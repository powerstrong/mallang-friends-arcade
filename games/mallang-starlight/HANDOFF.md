## 1. 현재 확정 결정

1. 말랑프렌즈 5종을 사용한다: 말랑 병아리, 모찌 토끼, 푸딩 햄스터, 라떼 강아지, 민트 고양이.
2. 첫 출시 로스터는 라떼 강아지(보호형)와 민트 고양이(원거리형)다.
3. 적은 고블린·오크가 아니라 삐걱봇·콩콩봇·반짝포탑·덩치곰 로봇 같은 오작동 장난감이다.
4. 밝은 구조 모험 톤. `사망/처치` 대신 `기운 소진/작동 정지/수리`를 쓴다.
5. 페이즈턴 유지, SPD 폐기.
6. 기본 피해는 고정값. 기존 ±15% 랜덤은 제거한다. RNG는 주입형 시드로만 제공한다.
7. 고정 성장, 퍼머데스 없음, 전투 후 무료 회복.
8. 목표는 전멸형만 쓰지 않고 길 확보·운반/탈출·장치 해제를 혼합한다.
9. 싱글플레이, localStorage, 메뉴 허브, 모바일 세로 우선, 무빌드 바닐라 JS를 유지한다.
10. `world/assets`와 `games/machine-animal-runner/assets`의 기존 말랑프렌즈 자산을 우선 재사용한다.

이전 HANDOFF의 “말랑프렌즈와 무관한 독립 판타지” 결정은 사용자 요청으로 명시적으로 무효화되었다.

## 2. 전술 명제와 첫 3개 작전

핵심 반복은 `위협 예고 → 위치 선택 → 친구 능력 연계 → 결과 확인`이다.

1. **공방 골목을 열어라**: 라떼로 길을 막고 민트가 뒤에서 지원한다.
2. **별빛 배터리를 옮겨라**: 6턴 안에 운반 목표를 탈출 칸으로 옮긴다.
3. **시계탑을 진정시켜라**: 양쪽 제어별 2개를 켠 뒤 덩치곰 로봇을 멈춘다.

플레이테스터가 이 세 작전의 서로 다른 트레이드오프를 설명하지 못하면 성장·장비·대량 아트로 넘어가지 않는다.

## 3. 현재 구현 현황

현재 작업트리에는 다음이 구현되어 있다.

- 8×8 격자, 라떼/민트 2인 고정 로스터
- 라떼 `든든막기`(인접 보호)와 민트 `별빛콩`(거리 3 무반격) 고유 특기
- 순수 상태/규칙 계층 + 직렬화 가능 상태 + 주입형 시드 RNG
- LoS 포함 공격 판정, 고정 피해, 맞대응, 적 AI
- 단일 합법수 생성기 기반 이동/공격/위협/상호작용
- `forecastEnemyPhase` 결정적 적 페이즈 예고(비파괴): 각 장난감의 의도·예상 피해·이동 예정 칸을 미리 계산해 UI가 `위협 예고`로 노출. 실제 결과와 정확히 일치
- 작전 3종
  - `alley-tutorial`: 전멸형 튜토리얼
  - `battery-run`: 배터리 픽업 → 운반 → 탈출
  - `clocktower-core`: 제어별 2개 활성화 후 보스 정지
- 홈 화면 → 브리핑 → 전투 → 결과 화면 루프
- localStorage 자동 저장과 이어하기
- 적 페이즈 중간 저장 금지와 구버전 적 페이즈 세이브 자동 재개
- PWA용 `manifest.webmanifest`
- 런타임 최적화 에셋(`assets/runtime/**/*.webp`, 앱 아이콘)
- WebAudio 절차적 사운드: 화면별 BGM 3테마 + 이벤트 효과음. 바이너리 오디오 없음, `save.sound` 토글로 일괄 제어

Phase 0 메커닉 프로토타입은 더 이상 “현재 결과물”이 아니라, 위 버티컬 슬라이스 알파의 기반 단계로 간주한다.

## 6. 테스트 불변조건

- 상태는 JSON 왕복 후 동일한 합법수를 만든다.
- 동일 상태·행동열·시드는 동일 결과를 만든다.
- 미리보기는 상태와 RNG를 소비하지 않는다.
- 합법 행동 확정은 RNG 스트림을 정확히 1회 전진시키며, 취소·불법 행동은 전진시키지 않는다.
- AI가 선택한 행동은 반드시 단일 합법수 목록에 있다.
- 벽 너머 원거리 행동과 맞대응은 불가능하다.
- 이동 취소는 위치·행동권을 바꾸지 않는다.
- 위협범위는 적의 실제 합법 공격 도달 칸과 일치한다.
- 목표 완료 여부는 UI 문구가 아니라 순수 상태에서 계산한다.

## 9. 작업 규약

- 사용자 응답은 한국어 존댓말.
- 별도 브랜치 없이 `main`에서 작업한다.
- 폴링/대기 루프 금지.
- `games/registry.js`에 `DRAFT` / `DIRECT_ONLY` / `NOT_SUBMITTED` 상태로 등록한다. 광장 공개 승격 전까지는 직접 URL 위주로 확인한다.
- 기존의 다른 게임/사용자 변경을 건드리거나 되돌리지 않는다.
- 문서와 실제 구현이 달라지면 같은 작업에서 HANDOFF/DESIGN을 갱신한다.
