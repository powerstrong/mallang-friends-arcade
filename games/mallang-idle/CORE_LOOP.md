# 말랑프렌즈 키우기 — 코어 루프

`mallang-idle` · 세로형 방치 RPG · 2026-08-15 확정

---

## 1. 한 줄 정의

> 말랑프렌즈가 **자동으로** 몬스터 웨이브를 밀고, 유저는 짧게 접속해 **성장·편성**하고
> **막힌 보스를 돌파**하는 세로형 방치 RPG.

**레퍼런스**: 사신키우기 · 레전드 오브 슬라임 계열.
**레퍼런스 아님**: 세븐나이츠식 대규모 수집 RPG / 단일 캐릭터 숫자 키우기 / 텃밭 · 다마고치.

---

## 2. 코어 루프 (P1 검증 대상)

```
자동 전투 → 골드 → 강화 → DPS 상승 → 스테이지가 빨리 밀림 → 보스 관문
                ↑                                              │
                │                            실패 → 같은 구간 재파밍
                └──────────────────────────── 돌파 → 다음 스테이지
```

이 5분이 재미없으면 위에 무엇을 쌓아도 소용없다. **유일한 1차 검증 대상.**

### 게이트 (사람이 판정)

> 5분 플레이하고 나서 **한 번 더 강화하고 싶어지는가.**

---

## 3. 전투 모델 — 횡스크롤 자동 전진

파티가 화면 왼쪽에서 오른쪽으로 계속 전진한다. 몹을 만나면 멈춰서 자동 공격하고,
처치하면 다시 전진한다. 스테이지당 일반몹 `MOBS_PER_STAGE`마리를 처리하면 보스가 등장한다.

```
[전진 0.6s] → [몹 조우 → 자동 공격 → 처치 → 골드] × 10 → [보스 등장] → 판정
```

### 규칙

| 항목 | v1 규칙 |
|---|---|
| 파티 규모 | **1명으로 시작.** 편성 확장은 P2 |
| 일반몹 | 반격하지 않는다. 소모하는 자원은 **시간뿐** |
| 일반몹 보상 | 처치 시 골드. 스테이지 진행도 +1 |
| 보스 | **DPS 체크.** `BOSS_TIME_LIMIT`(25초) 안에 못 잡으면 실패 |
| 보스 실패 | 스테이지 하락 없음. 같은 구간 일반몹을 반복 파밍하며 재도전 |
| 보스 재도전 | **자동 재도전이 공식 규칙** — 실패하면 같은 구간을 파밍하고 다시 도전한다. ON/OFF 토글은 v1 스펙에서 제외(엔진에 대기 상태가 없고, 끌 이유도 검증되지 않았다) |
| 캐릭터 사망 | **v1에 없음.** HP 성장축을 넣지 않으므로 죽지 않는다 |

### 왜 사망을 없앴나

보스 실패 조건을 "죽음"과 "시간초과" 둘 다 두면 성장 밸런스 변수가 두 배가 되고,
유저가 무엇이 부족한지 즉시 알 수 없다. 시간초과 하나로 통일하면 메시지가 명확해진다 —
**"공격력이 부족하구나."**

HP·방어가 의미를 갖는 자리는 P4의 던전이다. 그때 별도 규칙으로 도입한다.

## 4. 성장축 (v1 = 3축)

| 축 | 효과 | 성장 형태 |
|---|---|---|
| `ATK` | 공격력 | 지수 |
| `ASPD` | 공격 속도(회/초) | **선형 + 상한** |
| `GOLD` | 골드 획득량 배수 | 선형 |

`DPS = ATK × ASPD` 이므로 ASPD까지 지수로 두면 DPS가 이중 지수로 폭주한다. **ASPD는 선형에 상한을 둔다.**

### 일괄 강화 — `x1` · `x10` · `MAX`

골드 15M을 들고 버튼을 80번 누르게 만들면 그 순간 게임이 노동이 된다.
**연타를 게임성으로 삼지 않는다.** 첫 UI부터 세 버튼을 함께 만든다.

### 설계 의도 — 플레이어의 진짜 선택은 어디에 있나

ATK와 ASPD는 곱연산이라 **실질적 선택이 아니다** (언제나 가성비 좋은 쪽을 올리는 게 최적).
의미 있는 긴장은 둘뿐이다.

1. **지금 DPS에 넣어 돌파할까 / GOLD에 넣어 장기 성장할까**
2. **지금 보스를 재도전할까 / 더 파밍하고 갈까**

UI의 버튼 개수를 선택의 개수로 착각하지 말 것. 새 축을 추가할 때는
"이 축이 위 두 긴장 중 하나를 더 흥미롭게 만드는가"를 먼저 묻는다.

## 5. 오프라인 보상 — 골드만

8시간 만에 켰더니 `Stage 42 → Stage 167`이 되어 있으면 **내가 플레이한 느낌이 사라진다.**
오프라인은 진행이 아니라 **파밍**만 대행한다.

```js
elapsed = now - save.lastSaveAt
if (elapsed < 0) elapsed = 0                    // 시계 역행 방어
elapsed = min(elapsed, OFFLINE_MAX_HOURS)       // 8h clamp
gold += goldPerSec(safeStage) * elapsed * OFFLINE_EFFICIENCY   // 0.25
```

- `safeStage` = **보스를 돌파한 최고 스테이지** (현재 도전 중인 스테이지가 아니다)
- 스테이지 진행 없음. 경험치·장비도 v1엔 없음
- 복귀 시 `+1.82M 골드` 형태의 수령 팝업 하나로 끝낸다

치팅 방지는 프로토타입의 문제가 아니다. 위 clamp 세 줄이면 충분하다.
서버 권위가 필요해지는 시점은 [ROADMAP.md](ROADMAP.md)의 POST-v1이다.

## 6. 전투력 — 파생 UI 지표

상단에 `전투력 12.4K`는 당연히 있어야 한다. 다만 **표시 전용**이다.

```
전투력 = f(ATK, ASPD, 파티, 장비)     // 읽기 전용 파생값
```

전투력이 다시 데미지 공식에 곱해지는 구조는 **금지**한다. 그 순간 밸런스가 설명 불가능해지고
시뮬레이터 지표를 해석할 수 없게 된다.

## 7. 세계관 — 평화롭게 시작해 기계로 끝난다

스테이지 구간을 **챕터 데이터**로 분리한다. 챕터는 계속 덧붙일 수 있어야 한다.

| 구간 | 톤 | 적 |
|---|---|---|
| 초반 챕터 | 평화롭고 말랑한 산책 | 말썽꾸러기 수준. 위협이라기보다 장난 |
| 중반 챕터 | 이상 징후 | 기계 부품이 섞이기 시작 |
| 후반 챕터 | 긴장 | **기계군단**이 주요 적 세력 (`machine-animal-runner` 세계관 연결) |
| 이후 | 열어둔다 | 신규 챕터를 데이터로 추가 |

방치형의 숫자 인플레와 서사의 상승이 같은 방향을 향하게 만든다.
초반이 평화로운 것은 톤 선택인 동시에 **온보딩**이다 — 첫 3분에 위협을 주지 않는다.

```js
// data/chapters.js — 스테이지 구간 → 테마/적/배경
{ id:'meadow', from:1,  to:30,  name:'말랑 들판',   mobs:[...], bg:'...' }
{ id:'gears',  from:31, to:70,  name:'삐걱이는 언덕', mobs:[...], bg:'...' }
...
```

챕터가 늘어나도 전투 규칙은 바뀌지 않는다. 바뀌는 것은 외형과 계수뿐이다.
