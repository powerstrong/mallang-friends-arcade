# 말랑프렌즈 키우기 리뉴얼 설계 — 함께 모으는 말랑 산책

작성: 2026-11-22 · 상태: 설계안 · 이번 요청의 산출물은 이 문서뿐이며 코드·배포 변경 없음.
아래 6개 슬라이스는 한 번의 후속 구현 세션에서 순서대로 마칠 최소 범위다.
기준: 현행 세이브 v6, 무빌드 HTML/CSS/JS, UMD 엔진, Worker의 기존 D1 `DB` 바인딩.
소유자의 리뉴얼 지시로 POST-v1 착수 제한은 해제한다. 결정론·세이브 호환·지표 회귀는 유지한다.

## 1. 플레이어 관점 진단

- 아이에게는 “내 친구가 자랐다”보다 공용 공격력 숫자가 오른다는 느낌이 강하다. 친구는 합류 뒤 성장하지 않는다.
- 어른에게도 강화의 가성비를 고르는 반복이 중심이다. 챕터가 바뀌어도 풀어야 할 문제가 거의 같다.
- 도감은 구경한 기록이고, 직접 모아서 완성하는 작은 목표·보상이 약하다.
- 시련 3회를 한 번에 쓰고 과제를 받으면 다음 접속의 새로운 선택이 적다. 후반에는 보스 벽 체류가 길다.
- 저장이 사라지면 애착과 시간을 함께 잃는다. “다시 해도 괜찮다”는 신뢰부터 회복해야 한다.

## 2. 콘셉트와 핵심 루프

**친구들과 기계군단 때문에 잃어버린 말랑함을 되찾는 산책**으로 만든다. 짧게 들어와 모아 온 선물을 열고, 좋아하는 친구에게 마음방울을 주며, 오늘의 시련에 맞는 짝꿍을 골라 막힌 길을 넘는다. 구출된 작은 생명은 ‘말랑 알’에서 깨어나 도감의 산책 친구가 된다. 전투 동료 6명은 이야기 진행으로 확실하게 만나고, 알은 실패 없는 작은 수집의 즐거움을 맡는다. 어린이는 “선물 열기 → 친구 키우기 → 함께 도전”을, 어른은 성장 투자와 편성의 차이를 즐긴다. 모든 성장은 보존하고 이어하기 코드로 다른 기기에서도 산책을 계속한다.

```text
접속 / 코드로 복원 → 방치 선물 확인 → 지금 할 일 1개
                           │
자동 전투 → 골드 강화 → 보스 도전 ── 실패 → 조각 유물 / 파밍 선택 ─┐
                           └─ 돌파 → 새 길·친구·마음방울          │
                                               │               │
                       알 열기 ← 투자 선택 → 친구 레벨·별 성장 ─┘
                          │                       │
                   산책 도감·꾸미기          짝꿍 조합 → 오늘의 시련
                          └──────── 작은 성취·다음 목표 ────────┘
종료 → 로컬 저장 + 클라우드 백업 → 다음 접속의 선물
```

### 3.1 작은 수집과 친구 성장

- 전투 친구 해금은 현행 1/5/22/55/90/120층, 편성 자리는 1/10/40층 유지. 뽑기에 친구를 가두지 않는다.
- 신규 재화는 **마음방울 한 종류**. 본편 보스 최초 돌파마다 1개, 일일 과제 각각 1개, 출석 2개.
- 실패 보스·반복 파밍은 기존 골드/별조각만 지급. 최초 돌파 지급은 최고 기록으로 막아 반복 수급하지 못한다.
- 친구 육성은 10층 도달부터. 해금 친구 Lv.1, 비용 `2 + floor((현재 Lv.-1)/5)` 마음방울, 최대 Lv.20.
- Lv.5/10/20에서 별 1/2/3개가 자동으로 붙는다. 승급 실패·추가 재화·캐릭터 소모 없음.
- 패시브 효과 = 기존 효과 × `min(1.5, 1 + 0.02×(Lv.-1) + 0.04×별)`; 편성된 친구만 반영.
- 별은 레벨에서 파생하므로 중복 저장하지 않는다. 기존 공속 상한 5와 이동 시간 하한은 최종 적용한다.
- 짝꿍 3종: 모찌+라떼 ‘용감한 앞발’ 보스 +5%p, 푸딩+민트 ‘도시락 산책’ 골드 +5%p,
  피치+별사탕 ‘반짝 수색대’ 별조각 +10%p. 기존 `partyBonus`의 해당 축에 합산하며 시너지끼리 곱하지 않는다.
- **말랑 알**: 3층 최초 돌파에 첫 알 1개 선물. 이후 10층부터 마음방울 10개로 즉시 열기; 기다림 타이머 없음.
- 대상은 도토리·젤리·구름·태엽 생쥐·꽃 요정·별똥 아기의 ‘산책 모습’ 6종. 기존 몹 그림에 CSS 하트 테두리.
- 미보유끼리 동일 확률, 6종 완성 전 중복 없음. 완성 후 동일 확률 중복은 마음방울 2개로 반환.
- 완성 뒤에는 “모두 모았어요”를 기본 표시하고 재개봉은 접어 둔다. 자동 구매·개봉은 없다.
- 미리 “남은 N종 중 하나”와 비용·확률을 표시. 전투 성능은 없어 불운이 돌파를 막지 않는다.
- 알 비용 차감·추첨·보유 목록·RNG 상태를 한 상태 전이로 확정하고 즉시 저장한 뒤 1초짜리 열기 연출.
- `rng.js`에 정확한 상태 복원 API를 추가한다. 현재 `create(0)`이 1로 바뀌므로 저장된 RNG 상태 0도 그대로 복원해야 한다.
- 보상 RNG와 연출 RNG를 분리한다. 새 게임 시드는 앱 경계에서 주입, 마이그레이션 시드는 저장 필드의 안정적 해시로 생성.

### 3.2 매일의 산책과 쉬운 화면

- 별빛 시련: 최대 3회 보관, 8시간당 1충전, 신규 해금 시 3회. 가득 찬 동안 초과 충전은 쌓이지 않는다.
- 요일은 고정 KST 날짜를 주입해 결정한다. 월/목은 보스 패시브, 화/금은 공속 패시브, 수/토는 조각 패시브 효과 ×1.5; 일요일은 기본 규칙.
- 변칙은 시련에만 적용. 원본 편성·본편 수치는 불변이고, 공속은 변칙 적용 후에도 상한을 지킨다.
- 구버전 남은 횟수는 보존하고 첫 충전 기준을 전환 시각으로 둔다. 업데이트만으로 당일 3회를 다시 지급하지 않는다.
- 누적 출석 7칸은 방문한 새 날짜에 한 칸씩 전진, 빠진 날에도 초기화하지 않는다. 매회 마음방울 2개, 7칸 완성은 CSS 배지.
- 과제 목표는 날짜 시작의 `safeStage` 구간으로 고정: <30은 100처치/10강화/5도전,
  30~89는 150/15/7, 90+는 200/20/10. 기존 별조각 보상 3/3/5 유지 + 각각 마음방울 1.
- 신규 출석·마음방울 과제 보상은 육성과 같은 10층부터. 날짜 역행은 이미 지난 날의 재지급 사유가 아니다.
- 업적 6개: 첫 알, 알 3종, 알 6종, 첫 별 성장, 30층 돌파, 시련 10연승. 보상은 칭호/테두리뿐.
- 모래시계: Lv.0은 효율 25%·8h, 레벨마다 효율 +5%p, 최대 Lv.7에서 60%·12h.
  보관 시간은 `8 + min(4, floor(Lv.×4/7))`시간; 별조각 비용 기본 12, 증가율 1.8.
- 오프라인은 골드 파밍만 대행한다. 스테이지·친구 레벨·알 자동 개봉은 진행하지 않는다.
- 복귀 카드에 모은 시간·골드·현재 살 수 있는 강화량을 표시. “강화하러 가기”는 화면 이동만 하고 재화를 자동 소비하지 않는다.
- 탭은 ‘강화 / 친구 / 유물 / 도전 / 도감’. 친구 탭에 육성, 도감에 알·산책 배지, 도전에 출석·업적을 접어 넣는다.
- 상단에는 다음 목표 1개와 저장 상태. 재화는 사용하는 패널에서만 추가 표시한다.
- 숫자는 9,999 → 1만 → 1.25만 → 1억 → 1조. 비용은 올림, 보유량은 내림 표시하고 구매 가능 여부는 원값으로 판정.
- 온보딩은 첫 강화 → 첫 알 → 친구 육성 → 짝꿍의 순서. 한 번에 코치 1개, 스토리·복귀·저장 안내가 겹치지 않게 한다.
- 보스 안내는 “힘이 조금 더 필요해요”와 부족 비율, 상세에 초당 피해량. 실패 때는 얻은 조각과 다음 선택을 보여 준다.
- 응원은 피해 숫자를 만들지 않는다. 던전 리플레이 중 무대 탭은 기존 스킵 동작을 우선한다.
- 터치 영역 최소 44px, 키보드 포커스·읽기 라벨·`[hidden]` 가드·감속 모드 유지. 연출은 즉시 건너뛸 수 있다.

## 4. 사고 재발을 막는 저장 계약

### 4.1 발급·백업·복원

- 시작 화면에 ‘새 산책 / 코드로 이어하기’, 설정에 ‘이어하기 코드 / 백업 파일 내보내기·가져오기’를 상시 제공한다.
- 새 산책 시작 또는 기존 v6 진입 후 온라인이면 자동 등록한다. 코드 보관 안내는 첫 강화 뒤 한 번, 시작을 막지 않는다.
- 코드는 브라우저 경계의 `crypto.getRandomValues`로 만든 128비트 비밀값을 Base32 26자+검사문자 2자로 표시한다.
  4자씩 구분·복사·텍스트 파일 저장 제공. Worker 등록 성공 때만 “발급 완료”; 같은 코드로 생성 요청 재시도는 멱등.
- 코드는 세이브를 읽고 쓰는 열쇠다. 어린이에게 “보호자와 보관해요, 친구에게 공개하지 마세요” 한 줄 안내.
- Worker는 코드 SHA-256 해시만 보관한다. 코드 원문은 URL·분석·오류 로그·공유 게임 상태에 넣지 않는다.
- D1 `DB`에 `idle_saves(namespace, code_hash, revision, schema_version, payload, updated_at)`를 만든다.
  `(namespace, code_hash)`가 기본 키. 별도 `idle_save_backups`에 최근 정상본 3개와 충돌 탈락본 1개를 보관한다.
- 일상 백업은 하루 단위로 교체하고, 파괴적 교체·마이그레이션 전에는 직전 정상본을 남긴다. 무기한 매 업로드 이력은 만들지 않는다.
- API는 `POST /api/idle/saves` 등록, `GET /api/idle/save` 조회, `POST /api/idle/save` 조건부 저장.
  조회·저장은 `Authorization: Bearer <코드>`, 저장은 `baseRevision`·`requestId`·payload를 전송한다.
- 인증된 `GET /api/idle/save?backup=<revision>`으로 보관본을 내려받는다. 백업 조회 자체는 현재본을 교체하지 않는다.
- 각 응답에 `revision`·`serverNow`를 포함. 같은 요청 재전송은 이미 반영된 결과 반환; 본문 크기·버전·유한 수·배열 길이를 검증한다.
- 최근 요청 ID·반영 revision은 D1에 24시간 보관하고 CAS·백업과 함께 원자 처리한다. 만료된 요청도 낡은 baseRevision으로 재반영될 수 없다.
- 게임 상태는 공유 순수 검증 모듈로 검사하되 서버가 전투를 재실행하지는 않는다. 개인용 백업이며 서버 권위 경제는 아니다.
- 로컬 저장 5초, 변경이 있을 때 클라우드 업로드 30초. 알·성장·시련·과제 수령은 로컬 즉시 저장 후 2초 내 업로드 예약.
- 요청은 한 번에 하나, 중간 상태는 최신 스냅숏으로 합친다. 통신 실패 시 5/15/60/300초 간격으로 재시도한다.
- `visibilitychange`/`pagehide` 업로드는 보조 수단. 종료 요청 성공을 가정하지 않고 마지막 서버 확인 시각을 보여 준다.
- 상태 표시는 ‘이 기기에 저장 / 구름에 저장 완료 HH:MM / 연결되면 백업 / 저장 공간 부족’으로 구분한다.
- 코드를 아는 복귀 기기는 **조회·정합 확인 후** 자동 업로드를 켠다. 조회 실패·404에 빈 세이브를 올려 기존 저장을 대체하지 않는다.
- 오프라인 플레이는 가능하다. 다만 확인되지 않은 진행은 “백업 대기”이며, 기기 저장까지 지우면 마지막 업로드 이후 분량은 복원할 수 없다.
- 백업 파일은 코드 없는 게임 데이터로 기본 내보내기. 코드 보관 파일은 별도 동작이다. 가져오기 전 현재본을 백업한다.

### 4.2 충돌·중복 지급·손상 방어

- 정상 저장도 D1의 `WHERE revision = baseRevision` 조건부 갱신으로 경쟁을 막는다. 0행 갱신은 409와 최신본 반환.
- 충돌하면 같은 버전으로 변환한 두 정상 세이브를 순서대로 비교한다:
  **최고 돌파층 → 친구 총 레벨 → 알 보유 종류 수 → 누적 강화 수 → 누적 처치 수 → 활동 시간**.
- 첫 차이가 큰 쪽을 자동 채택한다. 모두 같으면 서버본 유지. `gold` 잔액·클라이언트 시각·세이브 버전은 진행도 점수가 아니다.
- 예: 80층에서 골드를 다 쓴 저장이 골드를 쌓은 79층보다 우선한다. 같은 층이면 친구를 더 키운 쪽이 우선한다.
- 승자의 **스냅숏 전체**를 선택한다. 재화 합산, 필드별 max, RNG·수령 기록을 서로 섞는 병합은 금지한다.
- 탈락본을 백업한 뒤 “더 멀리 간 산책을 이어왔어요”와 선택 근거 표시. 백업 내려받기로 다른 쪽도 회수할 수 있게 한다.
- 서버는 재시도에도 비교·검증·CAS를 적용한다. 충돌 후 새 revision만 붙인 낡은 요청이 최신본을 덮는 경로를 금지한다.
  모든 업로드에 진행도 하락 방어를 적용하고, 충돌 해결 요청은 최초 분기 revision을 유지한다. 완전 동률의 충돌은 서버본을 반환한다.
- 같은 브라우저의 멀티탭 정지 규칙을 유지하고, 클라우드 요청도 현재 소유 탭만 보낸다.
- 복원·오프라인 정산은 `offlineThroughAt` 이후 시간만 사용한다. 골드 지급과 커서 갱신을 하나의 로컬 스냅숏으로 즉시 저장한다.
- 온라인 복원은 조회 revision에 대한 정산본 CAS 성공 후 수령 완료 표시. 동시에 두 기기가 정산하면 하나만 반영되고 다른 쪽은 다시 조회한다.
- 오프라인 분기에서 각각 받은 보상은 나중에 전체 스냅숏 선택으로 정리한다. 둘을 합쳐 같은 시간을 두 번 지급하지 않는다.
- 알·과제·시련의 지급 상태도 연출 전에 저장. 재접속·스킵·응답 유실로 다시 지급하지 않는다.
- `lastSaveAt`은 호환용 스냅숏 시각, `offlineThroughAt`은 그 스냅숏이 정산한 시간의 끝이다. 활동 저장 때 둘을 함께 전진시킨다.
- 손상/상위 버전은 자동 저장·업로드 모두 중지하고 원문 보존 후 정상 백업 복원 안내. 현재 `restore()`의 새 게임 계속 실행 경로를 고친다.
- 코드·기기 로컬 연결 정보와 게임 payload를 분리한다. DEV 리셋·테스트 저장은 운영 클라우드에 쓰지 않는다.
- CORS는 idle 경로에서 Authorization 사전 요청을 처리한다. `shared/config.js`의 API 주소 선택을 재사용한다.
- 현재 staging도 운영 D1을 공유하므로 서버 설정의 `IDLE_NAMESPACE=prod/staging`으로 분리한다. 클라이언트 지정값은 받지 않는다.
- 생성·조회 남용은 D1의 짧은 수명 요청 카운터로 제한하고 만료분만 정리한다. 세이브를 기존 90일 로그 삭제 대상에 포함하지 않는다.

## 6. 밸런스 목표와 측정 방법

2026-11-22 현재 코드 실측: 정적 72개 통과(balance 40/UI 14/queue 18). 아래 현행값은 baseline 과제 모델.

- **24h 세션 `15/120` 목표:** 도달 170~210층, 활동 기준 최장 벽 ≤360초, 오프라인 골드 비중 65~85%.

- 세션 복귀 직후 골드 소비의 돌파 여유비는 연속 모델과 분리 관찰한다(현행 평균3.70). 연속 기준을 세션에 그대로 적용하지 않는다.
- 15/120은 하루 약 11회 접속하는 스트레스 모델이다. 아침·저녁 체감은 추가 `--hours=24 --sessions=10/710`으로 확인한다.
  이 보조 시나리오는 복귀마다 구매 가능 강화 ≥1회와 충전 시련 이용 가능, 오프라인 층 진행 0을 우선 검증한다.
- 새 지표: `firstHatchAt≤180초`, `hatchCount`, `uniqueCompanions`, `maxFriendLevel`, `starCount`, `heartEarned/spent`, `dungeonRuns`.
- 시뮬 정책: 첫 선물 즉시 개봉, 10층부터 20층 최초 돌파마다 알 1회 예산 예약(부족하면 대기, 6종 완성 시 중단),
  남은 방울은 편성 중 최저 레벨 친구에게, 동률은 캐릭터 정의 순서. 시련은 충전이 있고 활동 중이면 입장.
- 모래시계는 세션 모델에서 다음 레벨의 추가 방치 골드를 기존 유물 효율과 비교해 구매; 연속 모델에서는 구매하지 않는다.
- 기존 `bestAxis/bestParty`의 얕은 probe에 friends·시너지 원천을 반드시 전달하고, 레벨/변칙 변경에도 편성 캐시를 무효화한다.
- 새 CLI `--seed`를 구현해 1/7/42/2026 seed와 baseline/upper를 비교한다. 현재 CLI에는 seed 옵션이 없으므로 추가 전 사용하지 않는다.

- 실행 기준: `node games/mallang-idle/tools/sim.js --minutes=5 --json`, `--minutes=30 --json`, `--hours=24 --json`,

- 골드·DPS·가격의 유한성, 음수 잔액 0건, 결정론, 재화 원장 일치가 선행 조건. 기존 회귀 범위를 넓혀 목표를 맞추지 않는다.

## 7. 위험과 하지 말 것

- **과거 진행 복원 한계:** 이미 삭제됐고 다른 기기/내보낸 파일/백업이 없다면 정확한 옛 진행은 이 코드로 복원할 수 없다.
  이후 사고를 막는 설계다. 임의로 높은 층·보상을 넣고 “복구했다”고 표시하지 않는다.
- **코드 분실:** 계정이 없으므로 코드와 모든 로컬 사본을 동시에 잃으면 주인 확인이 불가능하다. 발급 성공과 외부 보관을 별개로 안내한다.
- **코드 유출:** 코드를 아는 사람은 저장에 접근할 수 있다. 짧은 방 번호 재사용, seeded RNG로 인증 코드 생성, 원문 로그 금지.
- **충돌의 한계:** 더 진행된 전체본을 고르면 다른 기기에서 쓴 재화·취향 선택 일부는 채택되지 않는다. 백업 없이 조용히 버리거나 재화를 합치지 않는다.
- **일시금 인플레:** v8 소급 방울·던전 최초 충전·출석이 겹친다. 기존 고층 세이브와 신규 세이브를 별도 측정하고 성장 상한을 지킨다.
- **수집 피로:** 희귀도·기간 한정·연속 출석 초기화·알 자동 연속 구매·구매 유도·광고 보상은 넣지 않는다.
- **애착 훼손:** 환생으로 층/친구를 지우거나 중복 친구를 먹이는 성장 금지. 부화 대상은 본편 친구를 대체하지 않는다.
- **구현 팽창:** 6명·수집6종·짝꿍3개·업적6개·모래시계1개로 고정. UI 프레임워크·새 이미지 생성·새 저장 서비스 도입 없음.
- **엔진 분열:** 시간·네트워크는 주입, 경제는 순수 API, 보상은 연출 전 확정. 렌더에서 피해 계산·RNG 소비·보상 지급 금지.
- **운영 착각:** staging의 운영 DB 공유를 잊지 않는다. 로컬 검증만으로 운영 복구 완료라 하지 않고 실제 API 배포·D1 migration·프런트 연결 확인을 별도 기록한다.
- **범위 밖:** 랭킹·PvP·광장 재화 공유·다른 상용 게임의 캐릭터/화면/고유 시스템 복제는 하지 않는다.
- **규칙 변경 기록:** 구현 시 RULES_REVIEW에 ‘서버 저장 보류 해제’, ‘가챠 금지→전투 친구 확정 해금+소형 알 수집’,
  ‘환생 제외 재승인’, R2/R4/R5 실행 결과를 남긴다. 이번 문서 작성으로 기존 규약 문서나 NEXT_STEPS를 수정하지 않는다.
