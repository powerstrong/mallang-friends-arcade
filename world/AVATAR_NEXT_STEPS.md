## P0-1. 모자·안경이 머리에 "붙어" 보이지 않음 (사용자 지적, 원인 실측 완료)

**증상**: 모자가 캐릭터 머리와 다르게 움직여 쓰고 있는 느낌이 안 남.

**실측 원인 2가지** (정본/레이어 시트의 셀별 콘텐츠 top(y) 측정, 384² 기준):

| 레이어 | 실측 | 문제 |
|---|---|---|
| 정본 바디 머리 top | row0 [10,10,10] / row1 [12,12,12] / row2 [15,15,15] | 행 내 균일(기준) — 머리 까딱임은 셀 그림 안의 기울기/1px 이동뿐 |
| 베레모 top | row0 [8,8,8] / row1 [9,9,9] / row2 [3,3,3] | **방향별 머리와의 간격이 앞+2 / 옆+3 / 뒤+12px** — 방향 돌 때 모자가 점프, 뒷모습에서 붕 뜸 |
| 안경 top | row0 [43,43,43] / row1 [43,38,38] | **옆모습 걷기 셀에서 5px 위로 점프** — 4박자 재생(A→정지→B→정지)마다 안경이 들썩 |

**원인 해석**: ① 착용 프롬프트(p5v2)의 "걷기 셀에서도 모자 위치·크기·각도는 정지 셀과 동일" 지시가 **캔버스 기준 고정**으로 해석돼 머리의 미세 움직임을 모자가 안 따라감 + ② 방향(행) 간 상대 높이 검수 기준이 없었음.

**수정 계획** (순서대로):
1. `scripts/avatar/process.py`에 **`--fit-head` 빌드 보정** 추가: 정본 두정(머리 top·cx)을 셀별로 측정해, 액세서리 레이어를 **셀 단위로 평행이동**시켜 "머리 top 대비 목표 간격"을 전 셀 동일하게 맞춘다(베레모=머리 top-2px 덮기, 안경=행별 idle 셀 기준). §12.5-11 "셀별 위치 보정은 정규화 단계에서"의 허용 범위 — **런타임 보정 금지(§5-4)와 혼동 금지, 이건 빌드 타임**.
2. 보정으로 부족한 것(뒷모습 베레모가 크기 자체가 큰 경우)만 **재생성**. 프롬프트 수정: "모자는 머리에 쓴 물체다. **각 셀에서 그 셀의 두상 위치·기울기를 정확히 따라 붙는다(두상 기준 상대 고정)**" + "뒷모습에서도 크기는 두상 폭의 0.9~1.1배" (기존 '정지 셀과 동일' 문구 삭제).
3. QA 게이트에 수치 추가: **액세서리-머리 상대 간격의 셀 간 편차 ≤1px** (위 측정 스크립트를 process.py `--metrics-only`에 편입).
4. 안경도 같은 흐름으로 재빌드. 완료 후 `wardrobe-preview.html` 4방향 걷기 육안 재검수.

## P0-2. 남녀 옷 구분 (사용자 지시 — 공용 옷장 정책 변경)

**지시**: "쿠키·젤리는 남자·여자인데 옷이 같은 게 말이 되냐. 치마류는 여자 것, 남자 옷은 따로."
→ 설계서 §3 "성별은 의상을 제한하지 않는다"(유니섹스 공용) 정책을 **사용자 확정으로 폐기**. 설계서 §3·§4에 개정 기록할 것.

**구현 계획** (공용 바디는 유지 — 에셋 호환은 그대로, 노출만 성별 필터):
1. 카탈로그 아이템에 `fit: 'girl' | 'boy' | 'all'` 태그(기본 `all`). **클라(shared/wardrobe_catalog.js)·서버(worker/src/wardrobe.js) 양쪽 미러** 동시 수정.
2. 기존 아이템 태깅 안: 복숭아 원피스·레몬 치마 = `girl` / 하늘 세트·딸기 티셔츠·라벤더 긴팔·청바지 = `all` (확정은 아빠 검수 때).
3. **남아 전용 라인 신설 생산**(착용-편집 파이프라인, 아래 레시피): 한벌 1(예: 공룡 후드 세트), 상의 1~2(체크 남방·네이비 맨투맨), 하의 1(카고 반바지). 여아 라인도 1~2벌 추가하면 옷장 대비가 산다.
4. 적용 지점:
   - 꾸미기 패널 아이템 그리드: `wardrobePreset` 기준 필터(`fit==='all' || fit===preset`).
   - `randomOutfit()`: 같은 필터 인자 추가.
   - `defaultSeparate()`: 이미 프리셋 취향 분기 있음 — 태그 기반으로 일반화.
   - sanitize: **관대 유지 권장**(비노출 원칙만 강제) — 프리셋 전환 시 기존 착장이 서버에서 강제 치환되는 혼란 방지. 서버 태그 검증은 B단계 옵션으로.
5. 프리셋 전환 UX: 패널 "처음으로 → 쿠키 기본"을 누르면 어차피 기본 코디로 리셋되므로 충돌 없음. 피커에서 저장 착장 복원 시 태그가 안 맞으면 프리셋 기본으로 치환(1줄).

## P2. UX 개선 (다음 세션 후보, 작은 것부터)

1. **✕ 닫기 시 편집 초안 유실** — 편집했는데 저장 안 하고 닫으면 조용히 폐기. "저장하고 나갈까요?" 한 줄 확인 또는 초안 자동 보관(패널 재오픈 시 복원).
2. **편집 중 매칭 모달 충돌** — 부스 위에서 꾸미기 열면 매칭 제안이 패널 뒤에 깔림. 편집 중엔 부스 후보 진입을 보류하거나(서버 아님, 클라 zone 안내만), 매칭 오면 패널 위로 안내 배너.
3. **저장 스로틀 드랍** — 서버 1초 스로틀에 걸린 저장은 조용히 사라짐(다음 저장은 됨). 클라에서 스로틀 감지 후 1초 뒤 자동 재전송하면 유실 0.
4. **신발 분리** — 현재 신발은 정본 바디에 베이크(분리옷이면 항상 같은 신발). v3 슬롯 후보.
5. **헤어 색 확장** — 팔레트 4색에 파랑·보라 등 추가(hair_palette.py 3단 치환이라 재생성 없이 빌드만).
6. **피커 카드 걷기 미리보기** — 사람 카드 선택 시 정면 걷기 재생(현재 정지 셀). 소소한 생동감.
7. **랜덤 코디 연출** — 🎲 누를 때 미리보기 반짝/회전 한 바퀴 등 작은 재미.

## P3. 기술 부채·인프라

1. **정적 배포 랙 20~40분(2026-08-17 관측)** — Cloudflare 쪽 git 연동 빌드가 병목. 대시보드(Workers & Pages → 프로젝트 → Deployments)에서 빌드 큐/실패 확인 필요. 저장소에서는 통제 불가 — **뱃지 버전(vNN)과 sw.js CACHE 동기 관례**로 반영 여부 판별(현재 v41).
2. **카탈로그 클라/서버 미러 수동 동기화** — 아이템 추가가 잦아지면 사고 확률↑(한쪽만 고치면 서버가 프리셋으로 치환 — "저장했는데 남에게 기본 코디" 증상). §11 CI 해시 비교를 B단계 전에 조기 도입 권장(worker/tests에 두 파일 파싱 비교 테스트 1개면 됨).
3. **속옷 비침의 근본 해결** — 분리옷 실루엣 규칙("탱크톱·반바지를 완전히 덮기")은 프롬프트 규율에 의존. 크롭티·짧은 치마를 열려면 **bare-base 시트**(속옷을 피부로 편집한 바닥 전용 시트) 1장 생산이 정공법(마네킹 비노출 원칙과 무관 — 바닥 레이어 전용).
4. **썸네일 캐시** — 아이템이 20+가 되면 LRU 24를 아바타/썸네일로 분리 검토.
5. **오프라인 첫 방문** — sw.js PRECACHE에 아바타 에셋 미포함(저우선, 재방문은 런타임 캐시로 커버).

## 함정 목록 (실측 누적)

- **부유 레이어 생성 금지** — 반드시 착용 편집("Image 1을 편집, 해당 아이템만 변경, 불변 조건 나열").
- **상·하의 프롬프트 2대 규칙**: ① "모든 9셀에서 X를 Y로 교체. 어느 셀에도 X가 보이면 실패" 강조(치마 1차가 지시 통째 무시, 차분 0px 전례) ② 실루엣은 탱크톱/반바지를 완전히 덮는 크기만. 추출 후 alpha px 즉시 확인.
- **액세서리 프롬프트에 "정지 셀과 동일" 금지** — 캔버스 고정으로 해석돼 머리를 안 따라감(P0-1). "두상 기준 상대 고정"으로 쓸 것.
- **align.json(row_dy=[0,4,10])은 마네킹 세대 고유값** — 마네킹 재생성 금지.
- 차분 추출 시 아이템 색이 마네킹 표면색(살구 피부·흰 탱크톱·회색 반바지)과 비슷하면 구멍.
- 크로마키 그린 #00FF00 + "방송용 그린스크린" 문구. 초록 계열 아이템은 마젠타 키 전환 필요(미구현).
- 분리옷 추출 단계의 `QA: FAIL`은 전신 지표를 부분 레이어에 적용한 노이즈 — 착용 시트 `--metrics-only` PASS + 합성 육안이 실제 게이트.
- `*.log`는 gitignore — 프롬프트 .md와 raw PNG만 커밋.
- `_mannequin.png` **단독** 렌더 경로 금지 — 분리옷 바닥 레이어로만(sanitize가 top+bottom 완비 보장).
- world.js는 IIFE 본문에서 buildPicker()가 즉시 실행 — 피커가 만지는 `let`은 선언을 위에(TDZ 전례 2회).
- 카탈로그는 클라/서버 2벌 미러 — 한쪽만 고치면 "저장했는데 남에게 기본 코디로 보임".
- wrangler dev는 `--assets` 없이 워커만 띄우면 reload 루프 없이 WS 검증 가능(스크립트는 저장소 밖에).
- 어떤 게임도 발사 URL의 characterId를 읽지 않음(자체 선택/서버 배정) — 말랑 친구 사전 선택 UI를 되살리지 말 것(설계서 §2).
